# Datasets

Every dataset used anywhere in `practice/` is a real file in this folder,
read from its full raw GitHub URL:

```
https://raw.githubusercontent.com/djnzx/ida-practice-3d/main/practice/datasets/<file>
```

No notebook in this course calls `load_iris`, `load_wine`, `load_digits`,
`make_blobs`, `make_moons` or `make_circles`. Data is acquired from a stated
address, or generated by visible code. See `practice/README.md` §6 for why.

## Field reference

One subsection per file, in the same order as the provenance table above.

### `titanic.csv`

891 passengers from the Kaggle training split. Three columns have missing
values and they are retained deliberately; Lesson 2 is built on them.

| Column | Type | Meaning |
|---|---|---|
| `PassengerId` | int | Row identifier, 1-891. Carries no information; Lesson 3 drops it. |
| `Survived` | int | The target. 0 = died (549), 1 = survived (342), so the classes are split about 62/38. |
| `Pclass` | int | Ticket class: 1 first (216), 2 second (184), 3 third (491). **Genuinely ordered** — first is above second is above third in price, deck and survival rate — so an integer encoding is appropriate here. |
| `Name` | text | Full name, 891 distinct values. An identifier, not a feature. It does carry a parseable title (`Mr` 517, `Miss` 182, `Mrs` 125, `Master` 40, plus `Dr`, `Rev` and others), which is a proxy for age, sex and social rank. |
| `Sex` | text | `male` (577) or `female` (314). Binary, so 0/1 encoding loses nothing. |
| `Age` | float | Age in years. **177 missing (19.9 %).** Ages under one are recorded as fractions (0.42, 0.67, 0.75, 0.83, 0.92); 96.5 % of the rest are whole numbers, which produces a visible comb in a fine-binned histogram. |
| `SibSp` | int | Number of siblings and spouses aboard, 0-8. 608 passengers travelled with none. |
| `Parch` | int | Number of parents and children aboard, 0-6. 678 travelled with none. `SibSp + Parch` is family size. |
| `Ticket` | text | Ticket number, 681 distinct values in 891 rows, with inconsistent formatting (`A/5 21171`, `PC 17599`, `113803`). Shared numbers indicate a party travelling together. One-hot encoding it would produce more columns than rows. |
| `Fare` | float | Fare paid, in pounds, 0 to 512.33. **15 fares of exactly 0**, which is a recording convention rather than a price. The upper tail is genuine first-class tickets, not error. |
| `Cabin` | text | Cabin number, e.g. `C85`. **687 missing (77.1 %)**, and not missing at random: 18.5 % missing in first class against 97.6 % in third. The leading letter is a deck, `A` to `G` plus one `T`. |
| `Embarked` | text | Port of embarkation: `S` Southampton (644), `C` Cherbourg (168), `Q` Queenstown (77). **2 missing.** Nominal with no ordering, so it needs one-hot encoding, not integer codes. |

### `iris.csv`

150 flowers, 50 of each species, with no missing values. The clean-data
baseline of the course.

| Column | Type | Meaning |
|---|---|---|
| `Id` | int | Row number, 1-150, in file order. Not a measurement; drop it before modelling or it will be treated as a feature. |
| `SepalLengthCm` | float | Sepal length in centimetres, 4.3 to 7.9. |
| `SepalWidthCm` | float | Sepal width in centimetres, 2.0 to 4.4. The weakest of the four for separating the species. |
| `PetalLengthCm` | float | Petal length in centimetres, 1.0 to 6.9. |
| `PetalWidthCm` | float | Petal width in centimetres, 0.1 to 2.5. |
| `Species` | text | The target: `Iris-setosa`, `Iris-versicolor`, `Iris-virginica`, 50 each. Note the `Iris-` prefix, which this CSV rendering adds. Setosa separates completely from the other two on either petal measurement; versicolor and virginica overlap. |

### `wine.csv`

178 wines grown in the same region of Italy by three different cultivars,
with thirteen chemical measurements each. No missing values.

The columns are on wildly different scales — `proline` spans about 1402
while `hue` spans about 1.23 — which makes this the course's standard
demonstration that any distance- or variance-based method must be given
standardised input.

**UCI publishes no units for these thirteen attributes**, and neither did
the original study. The ranges below are measured from the file; the
quantity each column names is chemically identifiable, but the scale it
was reported on is not recoverable from the documentation. That is worth
knowing rather than papering over: you can model this data perfectly well
without units, and you could not report a coefficient from it to a
winemaker.

| Column | Type | Observed range | Meaning |
|---|---|---|---|
| `alcohol` | float | 11.03 - 14.83 | Alcohol content. The range is consistent with percent by volume, though the file does not say so. |
| `malic_acid` | float | 0.74 - 5.80 | Malic acid, the dominant acid in unripe grapes. |
| `ash` | float | 1.36 - 3.23 | Inorganic residue remaining after combustion. |
| `alcalinity_of_ash` | float | 10.6 - 30.0 | Alkalinity of that residue. |
| `magnesium` | float | 70 - 162 | Magnesium content. Whole numbers, stored as floats. |
| `total_phenols` | float | 0.98 - 3.88 | Total phenolic compounds. |
| `flavanoids` | float | 0.34 - 5.08 | Flavanoid phenols. A subclass of `total_phenols`, so the two correlate at 0.86 almost by definition rather than by discovery. |
| `nonflavanoid_phenols` | float | 0.13 - 0.66 | The remaining, non-flavanoid phenols. |
| `proanthocyanins` | float | 0.41 - 3.58 | Proanthocyanins, a further phenolic subgroup. |
| `color_intensity` | float | 1.28 - 13.0 | Colour intensity. |
| `hue` | float | 0.48 - 1.71 | Hue. |
| `od280/od315_of_diluted_wines` | float | 1.27 - 4.00 | Ratio of optical density measured at 280 nm to that at 315 nm, on diluted wine. Note the `/` in the column name: it must be selected as a string, never by attribute access. |
| `proline` | float | 278 - 1680 | Proline, the most abundant amino acid in wine. Whole numbers stored as floats. **The largest-scaled column by two orders of magnitude**, so a PCA run without standardising reports it as 99.8 % of the variance. |
| `target` | int | 0, 1, 2 | The cultivar: 0 (59 wines), 1 (71), 2 (48). Nominal — the three cultivars have no natural ordering. |

### `mnist_sample.csv`

| Column | Type | Meaning |
|---|---|---|
| `label` | int | The digit, 0-9. 150 rows of each. |
| `p0_0` ... `p27_27` | int | Pixel intensity, 0-255, row-major. `p<r>_<c>` is the pixel at row `r`, column `c` of the 28x28 image, so a row recovers its image with `reshape(28, 28)`. |

The 784 pixel columns are far from independent: neighbouring pixels are
strongly correlated and the border pixels are almost always zero. That
redundancy is what makes the dataset a good subject for PCA.

### `bike_sharing_hourly.csv`

Reproduced from the UCI `Readme.txt` so that no notebook has to send a
student to a third-party page.

| Column | Type | Meaning |
|---|---|---|
| `instant` | int | Record index. |
| `dteday` | text | Date, `YYYY-MM-DD`, stored as a string and needing `pd.to_datetime` before any date arithmetic. |
| `season` | int | 1 spring, 2 summer, 3 fall, 4 winter. A category, despite the integer storage. |
| `yr` | int | 0 = 2011, 1 = 2012. |
| `mnth` | int | Month, 1-12. A category. |
| `hr` | int | Hour, 0-23. A category, and the strongest single predictor of demand. Its relationship with demand is not monotonic — peaks at 08:00 and 17:00-18:00 — and hour 23 is adjacent to hour 0, which an integer encoding denies. |
| `holiday` | int | 1 if the day is a public holiday. |
| `weekday` | int | Day of week, 0 = Sunday. A category. |
| `workingday` | int | 1 if neither weekend nor holiday. |
| `weathersit` | int | 1 clear or partly cloudy, 2 mist, 3 light snow or light rain, 4 heavy rain, ice pellets or snow with fog. Ordered by severity. |
| `temp` | float | Temperature in Celsius, **divided by 41**. |
| `atemp` | float | Apparent ("feels like") temperature in Celsius, **divided by 50**. |
| `hum` | float | Relative humidity, **divided by 100**. |
| `windspeed` | float | Wind speed in km/h, **divided by 67**. |
| `casual` | int | Rentals by non-registered users. |
| `registered` | int | Rentals by registered users. |
| `cnt` | int | Total rentals, the regression target. Equals `casual + registered`. |

Two traps in this file. The four weather columns were normalised by the
publisher, so they carry no physical units until you multiply them back;
a column between 0 and 1 labelled "temperature" should always prompt the
question. And `casual` and `registered` sum exactly to `cnt`, so using
them as features to predict `cnt` is target leakage — Lesson 3 uses that
fact.
